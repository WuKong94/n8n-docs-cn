# 模板提交指南 <a id="template-submission-guidelines"></a>

提交能够解决实际问题的原创工作流，确保导入后可运行，并包含其他用户使用所需的说明。

## 解决有用的问题 <a id="solve-a-useful-problem"></a>

确定具体受众和预期结果，说明模板处理什么任务，以及结果为何有用。

构建之前，先搜索[模板库](https://n8n.io/workflows/)。投稿应填补空白，或对现有做法作出实质改进。

模板需要有足够内容，能够为用户节省工作。只有一个触发器连接单个操作、默认聊天机器人或孤立 API 请求的模板，需要补充更多上下文或可复用逻辑才能符合要求。请将场景发展为完整解决方案，加入所需的数据处理、判断和设置。

例如，销售线索接收模板可以检查必填字段、匹配已有联系人、分派合格线索，并说明如何处理信息不完整的记录。

在满足问题需求的前提下，尽量保持设计简单。额外节点并不会自动让模板更有用。只要能够妥善处理特定问题，并提供可复用逻辑或知识，聚焦的工作流同样可以符合要求。

## 检查 AI 辅助投稿 <a id="review-ai-assisted-submissions"></a>

{% hint style="info" %}
**可以提交 AI 辅助完成的内容**

欢迎提交经过检查和测试的 AI 生成工作流、代码、表达式和设置说明。提交前，必须理解工作流如何运作，并验证其中的说法。
{% endhint %}

提交前请检查生成内容：

* 检查每个节点、表达式、代码片段、API 端点和依赖，替换虚构或不受支持的设置。
* 使用有代表性的输入运行工作流，检查输出（包括 AI 回复）是否准确、有用。
* 让设置说明与工作流一致，删除虚构功能、无依据的说法、泛泛填充内容及不适用的步骤。
* 检查链接、拼写和格式，改写重复信息却无助于设置或使用模板的文字。

不要提交未经检查的 AI 输出、大量近乎相同的工作流，或仅修改名称、提示词、应用选择的通用示例。这些属于低投入投稿，不符合质量要求。

## 提交原创作品 <a id="submit-original-work"></a>

请创建自己的模板，不要复制、转载或转卖他人的工作流。抄袭会导致账号封禁。

如果基于已有做法进行开发，请说明自己的贡献，并尊重原作者的许可和授权。

## 让工作流易于理解 <a id="make-the-workflow-understandable"></a>

* 为节点重命名，描述其用途，例如 **Find existing contact（查找已有联系人）**或 **Route incomplete submissions（分派不完整提交）**。
* 排列节点，让用户能够顺着执行路径理解流程。
* 遵循[便笺指南](sticky-note-guidelines.md)，包含一个概览便笺，并按要求添加分区便笺。
* 在可行时，将用户需要修改的值集中放在 **Edit Fields (Set)** 节点中，解释每个值，并使用清晰的占位符。
* 说明所需凭据、权限、外部资源，以及子工作流或社区节点等依赖。
* 加入使用场景需要的错误处理，说明需要人工关注的限制或失败情况。

假设用户可能刚接触 n8n，请将必需说明保存在模板中。可以补充详细设置指南链接或操作视频。

## 移除密钥和个人数据 <a id="remove-secrets-and-personal-data"></a>

使用 n8n 凭据进行身份验证，不要将 API 密钥、令牌、密码或授权请求头直接写入节点参数、代码、表达式或便笺。

提交前检查导出的 JSON。删除能够识别自己账号的凭据名称和 ID、个人邮箱、聊天 ID、表格 ID、Webhook URL 及其他私有资源标识。将可配置资源值替换为占位符，并说明设置方法。

移除敏感示例数据和固定的执行数据。如果工作流需要示例输入，请提供展示预期结构的合成数据。

## 提交前测试模板 <a id="test-the-template-before-submitting"></a>

测试准备提交的那份确切 JSON 文件。只能在原实例中运行的工作流，还不适合分享。

1. 导出工作流，再将其导入新的工作流。
2. 按照自己的设置说明配置凭据、替换占位符，不要依赖仅存在于原工作流的资源。
3. 使用有代表性的输入运行完整工作流。在目标服务中检查最终结果，而不只是查看执行状态。
4. 测试文档说明的每个分支，以及适用的缺失或空输入、多条记录和服务调用失败情况。
5. 检查重复执行。如果工作流会创建记录或发送通知，请验证去重处理，或说明何时可能重复。
6. 确认工作流不依赖固定数据、缺失的子工作流、本地文件或未说明的资源。
7. 对于 AI 工作流，尝试不同输入并检查回复，确认下游节点能够处理输出格式和预期失败情况。
8. 检查便笺、截图和设置链接是否与已测试工作流一致。

如果工作流依赖特定版本行为，请注明测试的 n8n 发布版本。说明所需节点或包版本及平台限制，不要声称未经核对的兼容性。

## 包含社区节点的模板 <a id="templates-with-community-nodes"></a>

列出每个社区节点包的名称，说明已测试版本，并链接到安装说明。

认证社区节点可能同时适用于 n8n Cloud 和自托管实例，未认证社区节点需要自托管。请检查具体包并说明受支持的配置。参阅[社区节点安装](../../integrations/community-nodes/installation-and-management/README.md)。

工作流使用社区节点时，请附上工作流图片，便于用户在预览无法渲染时查看，同时用文字提供设置说明。

## 提交检查清单 <a id="submission-checklist"></a>

[提交模板](README.md#submit-a-template)前，请确认：

* 模板解决实际问题，并为模板库增加价值。
* 内容由你创作，AI 生成部分已经检查。
* 导出的 JSON 导入后，按照说明设置即可运行。
* 已检查预期输出和相关失败情况。
* 已移除密钥、私有标识和敏感数据。
* 节点名称含义清晰，并添加了必需便笺。
* 工作流便笺写明了要求、设置步骤、行为和限制。
