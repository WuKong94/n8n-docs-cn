## 可持续使用许可证涵盖哪些源代码？ <a href="#what-source-code-is-covered-by-the-sustainable-use-license" id="what-source-code-is-covered-by-the-sustainable-use-license"></a>

[可持续使用许可证](https://github.com/n8n-io/n8n/blob/master/LICENSE.md)适用于我们[主要 GitHub 仓库](https://github.com/n8n-io/n8n)中的全部源代码，但以下内容除外：

* master 以外其他分支的内容。
* 文件名包含 `.ee.` 的源代码文件。这些文件采用 [n8n 企业许可证](https://github.com/n8n-io/n8n/blob/master/LICENSE_EE.md)。

## 什么是可持续使用许可证？ <a href="#what-is-the-sustainable-use-license" id="what-is-the-sustainable-use-license"></a>

可持续使用许可证是 n8n 于 2022 年创建的 fair-code 软件许可证。关于创建它的原因，可在此处了解更多。该许可证允许免费使用、修改、创建衍生作品和再分发，但有以下三项限制：

* 仅可为自己的内部业务目的，或非商业用途、个人用途使用或修改该软件。
* 仅可出于非商业目的，免费分发该软件或将其提供给他人。
* 不得更改、移除或遮蔽软件中许可方的任何许可、版权或其他声明。使用许可方的商标须遵守适用法律。

有关 n8n 社区版允许用途的实用说明，请参阅[许可证常见问题](./license-faq.md)。

我们欢迎任何希望使用可持续使用许可证的人。如果你在公开构建项目，尽早考虑许可问题有助于避免后续麻烦。如有相关问题，请通过 [license@n8n.io](mailto:license@n8n.io) 联系我们。

## 如果我希望以许可证不允许的方式使用 n8n，该怎么办？ <a href="#what-if-i-want-to-use-n8n-for-something-thats-not-permitted-by-the-license" id="what-if-i-want-to-use-n8n-for-something-thats-not-permitted-by-the-license"></a>

## 为什么不使用开源许可证？ <a href="#why-dont-you-use-an-open-source-license" id="why-dont-you-use-an-open-source-license"></a>

n8n 的使命是让每一位计算机使用者都具备强大的技术能力。我们认为，实现这一使命的最佳方式是在尽可能让更多用户免费使用 n8n 的同时，确保我们能够建立可持续、可行的业务。通过免费使用、便于分发和开放源代码，我们让所有人都能获得产品；通过商业运营，我们能够长期持续发布功能、修复缺陷，并大规模提供可靠软件。

## 为什么自行创建许可证？ <a href="#why-did-you-create-a-license" id="why-did-you-create-a-license"></a>

自行创建许可证原本是我们最不愿选择的方案。我们评估了现有许可证，确认没有一种符合特定需求后，才选择这条路。我们尝试通过两种方式减轻使用专有许可证带来的负担和阻力：

1. 使用通俗英语，并尽可能简短。
2. 推广 [fair-code](https://faircode.io/)，让它成为广为人知的统称，用于描述与我们类似的软件模式。

创建可持续使用许可证时，我们的目标是：

1. 尽可能宽松。
2. 保障我们建立业务的能力。
3. 尽可能清楚地说明哪些用途允许、哪些不允许。

## 公司禁止使用限制商业用途的代码，我还能使用 n8n 吗？ <a href="#my-company-has-a-policy-against-using-code-that-restricts-commercial-use-can-i-still-use-n8n" id="my-company-has-a-policy-against-using-code-that-restricts-commercial-use-can-i-still-use-n8n"></a>

只要出于内部业务目的使用 n8n，且没有将 n8n 提供给客户，让客户连接账户并构建工作流，你应当可以使用 n8n。如果不确定拟定场景是否属于内部业务目的，请查看[许可证常见问题](./license-faq.md)，或发送邮件至 [license@n8n.io](mailto:license@n8n.io)。

## 在可持续使用许可证下，我向 n8n 贡献的代码如何处理？ <a href="#what-happens-to-the-code-i-contribute-to-n8n-in-light-of-the-sustainable-use-license" id="what-happens-to-the-code-i-contribute-to-n8n-in-light-of-the-sustainable-use-license"></a>

在 GitHub 上贡献的任何代码都受 GitHub [使用条款](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#d-user-generated-content)约束。简单来说，你拥有所贡献的内容，并对其负责，同时授予其他 GitHub 用户使用这些代码的某些权利。向包含许可证声明的仓库贡献代码时，你以相同条款许可这些代码。

n8n 要求每位贡献者签署我们的[贡献者许可协议](https://github.com/n8n-io/n8n/blob/master/CONTRIBUTOR_LICENSE_AGREEMENT.md)。除上述内容外，该协议还允许 n8n 无需另行征求许可即可更改许可证，也意味着你不必为贡献承担责任，例如贡献对他人业务造成损害时。

可以从[这里](https://github.com/n8n-io)开始向 n8n 贡献代码；更多参与社区的方式列在[这里](../contribute/README.md)。

## 为什么从原先的 Apache 2.0 加 Commons Clause 改为可持续使用许可证？ <a href="#why-did-you-switch-to-the-sustainable-use-license-from-your-previous-license-arrangement-apache-20-w" id="why-did-you-switch-to-the-sustainable-use-license-from-your-previous-license-arrangement-apache-20-w"></a>

在 2022 年 3 月 17 日之前，n8n 使用 Apache 2.0 加 Commons Clause 许可。Commons Clause 由多家希望保护自身权益、应对云服务商的软件公司发起，其思路是在现有开源许可证之上增加商业限制。

但将 Commons Clause 作为开源许可证的附加条件，加上部分措辞存在解释空间，使使用条款产生了一些混淆和不确定性。Commons Clause 还限制了提供咨询和支持服务的能力。我们认识到，这些服务对于帮助用户从 n8n 中获益至关重要，因此希望移除这项限制。

我们创建可持续使用许可证，是为了更宽松、更明确地说明允许的用途，同时继续确保 n8n 获得构建和改进产品所需的资金。

## 可持续使用许可证与原先的 Apache 2.0 加 Commons Clause 有哪些主要区别？ <a href="#what-are-the-main-differences-between-the-sustainable-use-license-and-your-previous-license-arrangem" id="what-are-the-main-differences-between-the-sustainable-use-license-and-your-previous-license-arrangem"></a>

主要有两点区别。第一，我们收紧了软件使用方式的定义：以前 Commons Clause 限制用户“销售”软件，现在改为将使用限制在内部业务目的。第二，以前的许可限制了就软件相关的咨询或支持服务收费，现在我们完全取消了这项限制。

这意味着，你现在可以自由提供商业咨询或支持服务，例如构建 n8n 工作流，无需与我们另行签订许可协议。如果有意加入提供此类服务的 n8n 专家社区，可在此处了解更多信息。

## n8n 是开源软件吗？ <a href="#is-n8n-open-source" id="is-n8n-open-source"></a>

虽然 n8n 源代码按可持续使用许可证开放，但根据[开源促进会](https://opensource.org/)（OSI）的定义，开源许可证不能包含用途限制，因此我们不将 n8n 称为开源软件。实际使用中，n8n 为大多数用户提供了许多与 OSI 认可的开源软件相同的益处。

我们创造了 [fair-code](https://faircode.io/) 一词，用来描述我们以及其他开放源代码、但限制其源代码商业用途的公司的许可模式。

## 什么是 fair-code？它与可持续使用许可证有何关系？ <a href="#what-is-fair-code-and-how-does-the-sustainable-use-license-relate-to-it" id="what-is-fair-code-and-how-does-the-sustainable-use-license-relate-to-it"></a>

fair-code 不是一种软件许可证，而是描述符合以下特点的软件模式：

* 通常可免费使用，任何人都能分发。
* 源代码公开可用。
* 任何人都可以在公开或私有社区中扩展。
* 作者对商业用途施加限制。

可持续使用许可证是一种 fair-code 许可证。可在[这里](https://faircode.io/)进一步了解，并查看其他 fair-code 许可证示例。

我们始终乐于与感兴趣的人讨论软件许可证、fair-code 及代码共享的其他原则。如想交流，请发送邮件至 [license@n8n.io](mailto:license@n8n.io)。
