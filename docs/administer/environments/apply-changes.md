# 应用变更 <a id="apply-changes"></a>

应用变更会把工作内容从某个环境引入当前实例。项目级应用将选定变更引入一个团队项目；实例级应用则使整个实例与环境保持一致。

{% hint style="info" %}
**预览状态**

环境管理处于预览阶段，未来版本可能更改。在为生产实例设置此功能前，请先在测试实例上试用。
{% endhint %}

开始前，添加此实例要从中应用变更的环境。请参阅[规划环境](plan-your-environments.md)。

## 添加缺失的项目 <a id="add-missing-projects"></a>

项目级应用要求实例上已经存在对应项目。如果环境分支中包含此实例上尚不存在的团队项目，请先添加它们：

1. 前往 **Settings**（设置）> **Environments**（环境）。
2. 在 **Apply changes from（应用变更来源）**下的环境中，选择 **Apply（应用）**旁的 **Add N missing projects（添加 N 个缺失项目）**。
3. 选择要添加的项目。可选：在 **Assign a project admin（指定项目管理员）**下，为每个项目选择一个用户。
4. 确认 **Add N missing projects（添加 N 个缺失项目）**。

n8n 会创建空项目，使用源项目的 ID、名称、图标和描述，不会应用任何内容。如果分支中该项目包含工作流，请打开该项目并运行[项目级应用](#project-apply)。

不要手动创建这些项目。手动创建的项目会获得不同的 ID，因此即使名称相同，应用操作也不会将其匹配，项目仍会显示为缺失。

## 项目级应用 <a id="project-apply"></a>

项目级应用将选定的变更引入一个团队项目。该项目必须已存在于实例上，并具有源项目的 ID。请参阅[添加缺失的项目](#add-missing-projects)。项目级应用绝不会删除项目。实例上的所有项目共享标签，因此重命名标签会影响每个项目。

1. 打开一个团队项目。项目名称旁带向下箭头的徽标会显示传入变更的数量。
2. 选择该徽标，打开 **Changes to apply（待应用变更）**页面。
3. 选择要应用的工作流。n8n 会包含凭据、变量、数据表和标签等依赖资源。
4. 检查变更。每项资源会显示发生的变化，例如 **New（新增）**、**Modified（修改）**、**Renamed（重命名）**、**Moved（移动）**、**Archived（归档）**或 **Deleted（删除）**。要以可视化方式比较工作流，请选择 **Show diff（显示差异）**。差异查看器显示画布的 **Before（变更前）**与 **After（变更后）**，其中 Before 是当前实例，After 是环境分支。
5. 检查 **Blockers（阻碍问题）**选项卡并解决所有阻碍问题。请参阅[解决阻碍问题](#resolve-blockers)。
6. 选择 **Apply N changes（应用 N 项变更）**，然后确认。

## 解决阻碍问题 <a id="resolve-blockers"></a>

应用操作写入任何内容之前，n8n 会根据实例情况检查变更。项目级应用和实例级应用都会执行此检查。存在阻碍问题时，应用操作会停止，直到问题解决；在问题未解决期间，应用操作不会修改任何内容。

| 阻碍问题 | 处理方式 |
|---|---|
| 凭据或变量**缺失（Missing）** | 选择 **Add credential（添加凭据）**或 **Add variable（添加变量）**并创建资源。对于凭据，n8n 会预填源实例上使用表达式的字段；对于变量，会预填源实例上的值。属于其他项目的凭据则会显示为冲突。请参阅[跨项目依赖](known-limitations.md#cross-project-dependencies)。 |
| **无访问权限（No access）** | 凭据已存在，但项目无法使用。请让管理员将该凭据共享给项目。 |
| **冲突（Conflict）** | 实例上的资源存在应用操作无法解决的差异。按提示处理，然后刷新。 |
| **已移动（Moved）** | 分支中的工作流或文件夹位于另一个项目。项目级应用无法跨项目移动内容。请在实例上移动它，使其与分支一致，或者运行实例级应用。 |

## 确认破坏性变更 <a id="confirm-destructive-changes"></a>

应用操作在执行以下操作前会要求确认：

- 删除数据表列或更改列类型。这会删除这些列中的值，但保留行及其他列。
- 在实例级应用中删除项目。

## 实例级应用 <a id="instance-apply"></a>

{% hint style="danger" %}
实例级应用会覆盖每个项目，使其与环境分支一致，并删除分支中不存在的项目和内容。此操作无法撤销。请仅在源实例执行了实例级晋级后，或者备份实例后运行。
{% endhint %}

实例级应用适合让实例与其环境完全一致，例如初始化新的生产实例。对于日常变更，n8n 建议使用控制粒度更细的项目级应用。

1. 前往 **Settings**（设置）> **Environments**（环境）。
2. 在 **Apply changes from（应用变更来源）**下的环境中，选择 **Apply（应用）**。
3. 阅读警告并选择 **Apply（应用）**。
4. 如果 n8n 发现阻碍问题或破坏性变更，会打开对话框。解决问题、检查变更并确认。要删除分支中不存在的项目，请确认 **Delete N projects and apply（删除 N 个项目并应用）**。

## 应用操作会修改实例上的哪些内容 <a id="what-apply-changes-on-the-instance"></a>

应用操作会传递工作流、文件夹和数据表结构等工作内容的结构，不会传递凭据中的字面量密钥或数据表行等已存储内容。目前也不包含智能体。

| 资源 | 应用操作的行为 |
|---|---|
| 项目 | 实例级应用会创建分支上存在的项目，并在确认后删除分支上不存在的项目。项目级应用绝不会创建或删除项目。要添加缺失项目，请参阅[添加缺失的项目](#add-missing-projects)。 |
| 文件夹 | 在项目内创建、重命名和移动文件夹，使其与分支一致。项目级应用只修改包含选定工作流的文件夹。 |
| 工作流 | 创建或更新工作流。如果在源实例上删除了工作流，应用操作会在当前实例上将其删除，而不是归档。已归档的工作流保持归档状态。应用操作不改变工作流是否已发布。由应用操作创建的工作流处于未发布状态，需要在当前实例上发布。 |
| 凭据 | 将工作流关联到 ID 相同的凭据。如果凭据缺失，请在解决阻碍问题时创建。如果凭据已存在且属于该项目，应用操作会更新其名称及使用表达式的字段，保留密钥等所有其他值。 |
| 变量 | 变量必须已存在于实例上，或者在解决阻碍问题时创建，创建时会预填源实例上的值。应用操作绝不会修改已有变量的值。 |
| 数据表 | 创建表或更新表结构，保留已有行。删除列或更改列类型时，经确认后仅删除该列的值。 |
| 标签 | 创建标签并重命名，使其与分支一致。应用操作绝不会删除标签。 |

应用操作按以下方式匹配实例上的内容：

- **按 ID：**项目、工作流、凭据和数据表。
- **按名称和作用域：**变量。
- **先按 ID，再按名称：**标签。

晋级和应用使用 [n8n 包](../../build/manage-workflows/n8n-packages/README.md)导出和导入这些内容。

## 应用操作停止时 <a id="if-apply-stops"></a>

### 分支发生变化 <a id="the-branch-changed"></a>

如果在加载变更后有人修改了环境分支，应用操作会在写入任何内容前停止。项目级应用会显示 **The branch changed after the page loaded, so Apply didn't change anything.（页面加载后分支发生变化，因此未应用任何修改。）**；实例级应用会显示 **Apply paused（应用已暂停）**。检查最新变更后，再次应用。

### 无法应用 <a id="couldnt-apply"></a>

如果实例级应用失败，n8n 会显示 **Couldn't apply to the instance（无法应用到实例）**以及 **Some changes may already be applied（部分变更可能已经应用）**。n8n 不会回滚已作出的修改。应用操作旨在让实例与分支一致，因此可以再次运行以完成操作。

如果项目级应用失败，n8n 会显示 **Couldn't apply the changes（无法应用变更）**及以下提示之一：

- **Nothing changed（未作出任何修改）：**解决消息中指出的原因，然后重试。
- **The request may have run（请求可能已经执行）：**页面现已显示最新变更。再次应用前，请先检查。
